# Jev в терминале: пишешь задачу — агент работает

Настоящий интерактивный чат с рабочей папкой и историей. Ты вставляешь сообщение целиком и нажимаешь Ctrl+D или кнопку «Отправить». Enter добавляет новую строку. Агент читает файлы, создаёт и исправляет код, запускает команды и возвращает ответ. Следующее сообщение продолжает работу в той же папке.

Это отдельный запускаемый продукт к статье **Jev + Harness Engineering**. Браузер для работы не нужен. При старте ничего не проигрывается и никакая задача не отправляется автоматически.

## Запустить

Из каталога `terminal-agent`:

```bash
./setup.sh
./jev
```

Нужны Python 3.9+, macOS/Linux, установленный и авторизованный Codex CLI и ключ TypeSafe. В текущем авторском комплекте окружение уже подготовлено: достаточно `./jev`.

Для своего ключа установи переменную окружения, не записывая значение в историю shell:

```bash
read -s TYPESAFE_API_KEY
export TYPESAFE_API_KEY
./jev --doctor
./jev
```

После `read` вставь ключ и нажми Enter: ввод не отображается. Альтернатива для этого комплекта — локальный `.env.live` уровнем выше; читается только строка `TYPESAFE_API_KEY=…`, shell-код из файла не исполняется. Ключ не входит в репозиторий и не передаётся процессу Codex. Страница получения: [TypeSafe Keys](https://console.typesafe.ai/keys).

Проверка `--doctor` не вызывает модели. Она показывает наличие ключа, путь к Codex и версии библиотек. Для авторизации исполнителя используй `codex login`.

## Запрос, который можно вставить

```text
Создай CLI-анализатор инцидентов на Python без внешних библиотек: он читает JSONL, группирует ошибки по сервису и причине, убирает дубли event_id, правильно сравнивает часовые пояса и пропускает битые строки с предупреждением. Добавь пример связанных сбоев и ложный след, сохраняй JSON- и Markdown-отчёт с event_id, отделяй гипотезу о причине от доказанных фактов. Напиши и запусти unittest-тесты, выполни CLI на примере. В конце дай команду запуска. Реально создай файлы в текущей папке.
```

Нажми **Ctrl+D** или кнопку **«Отправить»**. Затем можно написать обычным текстом: «Добавь фильтр по сервису и тест на него» или «Объясни, какие выводы отчёта подтверждены событиями». Это новые живые ходы, не заранее подготовленные ветки.

Оба сервиса используют твои доступные лимиты. Модель Codex берётся из текущих настроек CLI; версия Jev закреплена как `jev-1.13.0`. При ошибке API появляется причина остановки, синтетическая замена не включается.

## Что показывает терминал

- Слева — разговор и реальные инструменты: запущенная команда, stdout, код завершения, изменения файлов.
- Вверху — граф наблюдаемых этапов. Jev route → Codex → проверки → Jev review → результат. Повторный ремонт появляется только при фактическом новом вызове.
- Справа — ответ Jev: варианты, вероятности, возвращённый `confidence`, Noul соответствия запросу; ниже — проверки и изменённые файлы.
- Внизу — время, число вызовов, токены Jev и worker отдельно. Это счётчики провайдеров, не оценка денежной стоимости.

В узком терминале боковая панель скрывается; `/status` выводит те же данные в разговор. Для одновременного обзора удобно окно от 100 колонок.

Поле ввода многострочное: сохраняет абзацы при вставке, переносит длинные строки и растёт по мере заполнения. **F4** разворачивает редактор почти на весь экран; большой текст можно прокручивать. **Enter** добавляет строку, **Ctrl+D** отправляет всё сообщение. **Ctrl+Enter** тоже поддерживается, если терминал передаёт это сочетание.

Клавиши: **F1** меню, **F2** вставить пример без отправки, **F3** полный журнал, **Ctrl+S** сохранить текущий экран в SVG, **Ctrl+C** остановить работающую задачу или выйти из пустого чата. `/stop`, `/status`, `/clear`, `/help`, `/quit` доступны в строке ввода. Очистка экрана не стирает историю на диске.

## Где результат

Без дополнительных аргументов каждый запуск создаёт отдельную папку:

```text
.sessions/<session-id>/
  workspace/              файлы, которые ты поручил создать
  session.json            история и параметры
  events.jsonl            последовательность наблюдаемых событий
  screenshots/            экраны по Ctrl+S
  turn-001/
    request.json          твой запрос
    jev-*/                запросы и реальные ответы Jev
    worker-*/             поток Codex, задание, финальный ответ
    *-checks.json         исполнение проверок
    result.json           результат хода и счётчики
```

Путь рабочей папки постоянно виден в шапке. Продолжить последнюю сессию:

```bash
./jev --resume last
```

Работать в своём существующем проекте:

```bash
./jev --project /absolute/path/to/project
```

В этом режиме Codex меняет выбранный проект. Он работает с `workspace-write`; объяснения и исследование, выбранные Jev, получают `read-only`. Сетевые инструменты, запросы повышения прав и веб-поиск у worker отключены. Встроенный harness выполняет локальные проверки отдельно. Уже внесённые изменения при `/stop` сохраняются.

## Как именно используется Jev

Jev — модель для типизированных решений, а не генератор реплик. В начале Choice выбирает режим `implement`, `inspect` или `answer`. Программа использует его для задания прав и контекста исполнителю. При confidence ниже 0.25 сначала выбирается чтение/уточнение.

Codex генерирует ответ и код, использует инструменты и при необходимости составляет план. Его JSONL-события отображаются по мере поступления. Программа не показывает вымышленное «мышление» модели.

После worker harness выполняет проверки. Затем Jev получает результат, изменённые файлы и текстовое утверждение исполнителя; Choice предлагает `finish`, `improve` или `ask_user`, а Noul оценивает соответствие текущему запросу. Python ограничивает попытки, проверяет фактические провалы, отсутствие прогресса и отмену. Высокая оценка Jev не отменяет упавший тест.

Пороги 0.25/0.60 и 0.50 в policy — настройки этой первой реализации, не измеренная универсальная надёжность. Максимум три попытки worker и пятнадцать минут на ход; одна попытка worker ограничена восемью минутами, один API-запрос Jev — 20 секундами. Отмена уничтожает группу процессов, а не только строку прогресса.

## Что означает финальный статус

**«Ответ подготовлен»** — разговорный ход завершён. **«Результат подготовлен»** — worker создал артефакт; выполненные тесты перечислены, но отдельного независимого контракта нет. Сгенерированные самим worker тесты не становятся независимой приёмкой.

**«Проверки контракта пройдены»** — заранее зарегистрированные проверки выполнены на актуальном снимке файлов и прошли. Это утверждение ограничено их контрактом. Новое требование из следующего сообщения может выходить за его пределы.

Для своего проекта можно заранее создать `jev-checks.json`:

```json
{
  "checks": [
    {
      "id": "regressions",
      "title": "Существующие регрессионные тесты",
      "argv": ["python3", "-B", "-m", "unittest", "discover", "-s", "tests", "-v"]
    }
  ]
}
```

Это доверенная конфигурация пользователя. Аргументы передаются без shell-интерполяции. Команды фиксируются при создании сессии; существующая папка `tests`, конфигурация и файловые аргументы команд защищаются хешами. Если worker изменит контракт, приёмка остановится. При намеренной смене требований создай новую сессию с обновлённым контрактом.

Без такого файла harness может выполнить найденные `tests/test*.py` или `test*.py` в корне через unittest, но пометит их как проверки проекта, которые мог написать сам worker. «0 тестов» не считается успешной проверкой.

## Отдельная сложная миссия

```bash
./jev --mission loglab
```

Создаётся копия многофайлового анализатора с четырьмя дефектами: временные зоны, дубли событий, битые строки и severity. **F2** вставит задание для этой миссии; ты сам отправляешь его Ctrl+D. Внешний oracle содержит шесть проверок и не копируется в рабочую папку. Исходный проект проходит одну из шести.

## Проверить сам агент

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

Тесты протокола используют явно подставленных исполнителей; проверки subprocess реально запускают процессы и проверяют отмену потомков. Живые запуски и их свидетельства хранятся отдельно в `verification/`.

Для интеграций есть явно неинтерактивная команда `./jev --run 'текст'`, возвращающая JSONL. Обычный `./jev` всегда ждёт твоего ввода.
