# CLI-анализатор инцидентов

Python 3.9+, только стандартная библиотека; установка зависимостей не нужна.

Из папки проекта запустите пример:

```sh
python3 incident_analyzer.py examples/related_failures.jsonl --json-report reports/incidents.json --markdown-report reports/incidents.md
```

Отчёты сохраняются в JSON и Markdown с `event_id`. Каталоги создаются автоматически,
существующие отчёты заменяются. `-` вместо входного файла читает stdin.
Справка: `python3 incident_analyzer.py --help`.

Каждая непустая строка JSONL — объект в UTF-8 с обязательными полями `event_id`,
`timestamp`, `service`, `level`, `reason`; необязательные поля — `trace_id`,
`upstream_service`. Время задаётся в ISO 8601 с часовым поясом (`Z` или `±HH:MM`).

Анализатор сравнивает время в UTC, сохраняет первую валидную запись каждого
`event_id` и группирует ERROR/CRITICAL/FATAL по сервису и нормализованной причине.
Битые строки пропускаются с номером строки и предупреждением в stderr и отчётах.
Одиночные Unicode-суррогаты в предупреждениях экранируются как `\ud800`;
обычный Unicode сохраняется.

Факты и гипотезы разделены: совпадение трассы, зависимости и временного окна
(по умолчанию 120 секунд) поддерживает гипотезу, но не доказывает первопричину.
В примере есть цепочки `database → api → web` и ложный след `noise-001` (telemetry).
Ожидается: 7 ошибок, 4 группы, 2 гипотезы, 2 дубля, 2 битые строки и 3 предупреждения.

Запуск тестов, включая проверку Unicode в предупреждениях и реальные вызовы CLI:

```sh
python3 -m unittest discover -v
```

Код завершения: `0` — оба отчёта записаны (возможны предупреждения),
`2` — ошибка аргументов, чтения или записи.
