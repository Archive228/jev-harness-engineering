# Crypto Ledger — учёт синтетических сделок

Синтетические сделки; внешние API, ключи бирж и реальные деньги не нужны.
Нужен Python 3.9 или новее, используется только стандартная библиотека.
Запускайте из этой рабочей папки:

```bash
python3 -B cryptoledger.py examples/trades.csv --json report.json
python3 -B -m unittest discover -s tests -v
python3 -B -m unittest discover -s regression_tests -v
```

CLI создаёт каталог отчёта, при необходимости перезаписывает JSON и выводит
счётчики. Отклонённые записи дают предупреждения в stderr и в JSON. Ошибка чтения,
заголовка или записи файла завершает команду с кодом 2; ошибки отдельных сделок
не мешают сохранить отчёт (код 0). Пустой CSV допускается.

CSV: `trade_id,timestamp,symbol,side,quantity,price_usdt,fee_usdt`.
Время обязано содержать timezone. `side` равен `buy` или `sell` без учёта регистра;
символ нормализуется в верхний регистр, ID и символ не пусты. Количество и цена
строго положительны, комиссия неотрицательна; все Decimal конечны.
Первая валидная строка ID побеждает, даже если раньше была невалидная с тем же ID.
Пробелы по краям текстовых полей убираются; регистр ID сохраняется. Проверка строки
предшествует дедупликации: невалидный повтор попадает в `rejected_rows`, валидный —
в `duplicate_rows`. Дубликаты не меняют суммы и timeline. Пропущенные или лишние
значения CSV отклоняются. Поддерживается UTF-8, в том числе с BOM.

JSON: `accepted_rows`, `duplicate_rows`, `rejected_rows`, `warnings`, `timeline`,
`symbols`. В `timeline` нужны `trade_id` и `timestamp` в ISO UTC с шестью цифрами
микросекунд и `Z`; порядок — UTC, затем trade_id. Для каждого символа нужны строки
Decimal `net_quantity`, `net_cashflow_usdt`, `fees_usdt`; масштаб строки произволен.
Покупка: cashflow = −quantity×price−fee. Продажа: +quantity×price−fee.
Для каждой отклонённой строки — отдельное предупреждение в `warnings`.
Номер строки данных в предупреждении начинается с 1, без заголовка. Ошибки синтаксиса
CSV также учитываются; чтение продолжается, если CSV-парсер может выделить следующую
запись. Незакрытая кавычка может поглотить остаток файла в одну повреждённую запись.
Пустой вход даёт нулевые счётчики, пустые timeline, warnings и symbols.

`ledger.analyze(rows)` принимает итерируемые словари с полями CSV. Для чисел подходят
строки, `Decimal` и целые числа; `float` и булевы значения отклоняются. Все суммы
и произведения считаются через `Decimal` с точностью, достаточной для операндов;
в JSON они сохраняются строками без преобразования в `float`.

В примере принимаются 3 сделки, 1 валидный дубликат и 1 отклонённая запись (`NaN`).
BTC: `net_quantity = 0.06`, `net_cashflow_usdt = -3524.24`, `fees_usdt = 4.24`.
ETH: `net_quantity = 1.5`, `net_cashflow_usdt = -3001.5`, `fees_usdt = 1.5`.

Покупка увеличивает `net_quantity`, продажа уменьшает; комиссии всегда вычитаются
из денежного потока и отдельно суммируются в USDT. Начальный остаток равен нулю,
поэтому продажи могут дать отрицательный остаток количества. Рыночная стоимость
оставшихся монет не рассчитывается.

Это **учёт денежных потоков и остатка количества**, не расчёт PnL, не торговая
стратегия и не рекомендация купить монету.
Тесты в `tests/` и `jev-checks.json` заданы до запуска агента и менять их нельзя.
Дополнительные регрессионные тесты находятся отдельно в `regression_tests/`.

## Как читать отчёт Crypto Ledger

В `report.json` показатели `symbols.BTC` — строки точных сумм `Decimal`; единицы — BTC и USDT.
Покупка `0.10 BTC` по `60000 USDT` с комиссией `3 USDT`: поток `−0.10 × 60000 − 3 = −6003 USDT`.
Продажа `0.04 BTC` по `62000 USDT` с комиссией `1.24 USDT`: поток `0.04 × 62000 − 1.24 = 2478.76 USDT`.
`net_cashflow_usdt = -3524.24`: сумма потоков `−6003 + 2478.76`; на столько USDT расходы превысили поступления.
`net_quantity = 0.06`: остаток `0.10 − 0.04 BTC` при нулевом начальном количестве.
`fees_usdt = 4.24`: сумма комиссий `3 + 1.24 USDT`, уже вычтенная из потока; повторно вычитать её не нужно.
Повторный валидный `btc-buy` исключён: в суммы входит только первая валидная строка с этим ID.

**Денежный поток не равен PnL:** `−3524.24 USDT` не означает такой убыток — в остатке ещё `0.06 BTC`.
Для реализованного PnL нужна себестоимость проданного, для нереализованного — текущая оценка остатка; CLI их не рассчитывает.
```bash
python3 -B cryptoledger.py examples/trades.csv --json report.json
```
