# Почему терминальный агент устроен так

Проверено 20 сентября 2026 года по документации TypeSafe, исходным проектам и материалам нашей лаборатории. Это обоснование конструкции; фактические результаты конкретного запуска находятся в его журнале.

## Два разных типа работы

Пользователь пишет обычное задание. Генеративный worker читает проект, составляет план, пишет код и отвечает словами. Jev получает короткое описание текущего состояния и отвечает на конкретные вопросы: какое направление подходит, относится ли результат к запросу, достаточно ли приложенных фактов для конкретного утверждения. Программа связывает эти ответы с выполнением и сохраняет события.

```text
запрос → генеративный worker → файлы, команды, наблюдения
                                  ↓
                         Jev: типизированные оценки
                                  ↓
                  код: продолжить, проверить, остановиться
```

Jev не генерирует свободный текст. Для плана, программного кода и разговора нужен генеративный компонент. TypeSafe прямо описывает это ограничение; LangChain предлагает сочетать Jev с моделью, ведущей агента. [Jev 1.13: ограничения](https://docs.typesafe.ai/model-jaggedness/jev-1.13), [Building a Harness with Jev](https://www.langchain.com/blog/building-a-harness-with-jev).

## Что можно поручить Jev

- **Choice** выбирает один вариант из явного списка. Уместен для направления работы или выбора следующей доступной диагностики. Если подходящего варианта может не быть, нужен `none_suitable`.
- **Noul** оценивает вероятность конкретного утверждения. Например: «Поддерживает ли приложенный вывод проверки утверждение о поиске по описанию?»
- **Score** оценивает одну описанную шкалу. Это не счётчик выполненных работ и не способ точно вычислить число.

Вопросы одного запроса оцениваются независимо и не получают ответы соседних вопросов. Если инструмент принёс новые факты, для оценки этих фактов нужен новый запрос. Название поля вопроса не заменяет его полные `instructions`: модель не видит ID вопроса. [Официальный skill TypeSafe](https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md), [Choice](https://docs.typesafe.ai/primitives/choice).

При выборе действия описываем реальные доступные варианты. При проверке утверждения передаём само утверждение и относящиеся к нему наблюдения. Полный репозиторий или длинный неотфильтрованный лог увеличивает шум. Арифметику, exit codes, сроки, лимиты и сравнение снимков файлов вычисляет код. [Jev 1.13: ограничения](https://docs.typesafe.ai/model-jaggedness/jev-1.13).

## Что означают полоски и статусы

`probabilities` и `confidence` берём из ответа сервиса. Максимальная вероятность и confidence — разные поля. В официальной странице confidence не опубликована универсальная формула его пересчёта через `p_max`; интерфейс не должен выдавать такую формулу за контракт API. Порог относится к нашей политике и требует проверки на нужном классе задач. [Confidence](https://docs.typesafe.ai/confidence).

Завершение процесса worker, успешный тест и подтверждение всей задачи — разные факты. Сообщение модели «готово» не заменяет результаты команд. Высокая оценка Jev тоже не является независимым доказательством корректности. Для явно заданного контракта нужны свежие проверки текущего результата. Для свободного задания отчёт перечисляет созданные артефакты и фактически выполненные проверки, сохраняя непроверенные утверждения отдельно.

Граф в терминале показывает наблюдаемые стадии, вызовы, команды и переходы программы. Это журнал работы, а не визуализация внутренних рассуждений модели. Записанный прогон должен быть обозначен как replay; фикстуры — как demo. Живой запрос должен иметь собственные ответы API, временные метки и результат.

## Из каких источников взяты полезные конструкции

- [Function calling](https://docs.typesafe.ai/cookbooks/function_calling): выбор обработчика и его аргументов из закрытых наборов, исполнение обычным кодом.
- [Skill suggestion](https://docs.typesafe.ai/cookbooks/skill_suggestion): ранжирование кандидатов, затем проверка короткого списка с возможностью отвергнуть все варианты. Это пример для расширения агента, а не обещание встроенной библиотеки skills.
- [Foreman](https://github.com/thruwire/foreman): отдельные генеративный worker и семантический supervisor, ограниченная политика действий, наблюдения и журнал событий. Это сторонний архитектурный эксперимент. Его авторы отдельно описывают [границы доказательства](https://github.com/thruwire/foreman/blob/main/docs/what-foreman-proves.md); успешное демо не устанавливает общую надёжность или выигрыш относительно других агентов.
- [Наша проверка источников](../source-check.md) и [лаборатория](../jev-harness-lab/README.md): уже испытанные API-контракт, сохранение запросов и ответов, проверка свежести фактов и явные причины остановки. Старый `jev-console.html` показывает сохранённые прогоны. Новый запрос пользователя требует интерактивного терминального запуска на введённом задании.

Новый терминал развивает эти конструкции. Ссылки обозначают источники архитектурных решений, а не утверждение, что сторонние авторы проверяли нашу реализацию.
